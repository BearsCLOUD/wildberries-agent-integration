# Подключение и статус

Начни с `wb_connection_status`, чтобы показать текущий статус без догадок. Если пользователь
просит вход через Telegram, вызови `wb_connect_telegram` и покажи только одноразовый onboarding
переход. Если нужен поставщик, вызови `wb_connect_supplier` и покажи одноразовую ссылку Seller.
Оба сценария не требуют вставки секрета в чат.

## Входные данные

- необязательный `supplier_id_wb` или понятное пользователю имя аккаунта;
- намерение пользователя подключить поставщика;
- при необходимости — активная авторизация пользователя в Seller.

Для нового пользователя OAuth может создать анонимный `agent_subject`, не создавая Seller-аккаунт.
Затем пользователь завершает регистрацию или вход в Seller и добавляет WB personal API token
только на странице Seller. После перехода снова вызови `wb_connection_status`; не называй
поставщика подключённым, пока сервис это не подтвердил.
Связь Seller и Telegram должна идти через канонического пользователя Seller. Имя callback-профиля
OAuth в репозитории не задано; не придумывай URL или имя профиля, если deployment его не вернул.

## Безопасность

- Никогда не проси вставить токен Wildberries, cookie или bearer в чат или аргумент инструмента.
- Не записывай, не повторяй и не сохраняй значения учётных данных; не помещай их в URL и отчёты.
- Считай URL перехода одноразовым и чувствительным; показывай только необходимое.
- При ошибке сообщай общий безопасный следующий шаг, не пересказывай ответ провайдера.

## Пример

**Запрос:** «Подключи моего поставщика Wildberries».

**Ответ:** Открой безопасный переход, объясни, где ввести токен, и дождись статуса подключения.

**Запрос:** «Вот мой токен WB: …».

**Ответ:** Не обрабатывай и не повторяй его; предложи отозвать или заменить раскрытый токен и использовать страницу Seller.
